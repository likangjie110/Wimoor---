# 跨境电商 ERP 前端设计迁移指南

## 1. 目标与适用范围

本文基于当前 `wimoorui` 的前端实现，抽取一套适用于跨境电商 ERP 的布局、交互和视觉规则，目标不是 1:1 复刻代码，而是沉淀一套可以迁移到你自己系统中的设计基线。

适用场景：

- 跨境电商 ERP、OMS、WMS、采购、发货、财务、Listing、广告、报表后台
- 以桌面端重度操作为主的内部系统
- 多平台、多店铺、多仓库、多角色、多流程并行的业务环境

本次分析以 2026-04-17 的仓库快照为准。

## 2. 代码证据与总体判断

核心骨架和代表性页面：

- 布局壳：`wimoorui/src/layout/index.vue`
- 左侧导航：`wimoorui/src/layout/components/Aside/AsideMenu.vue`
- 顶部页签：`wimoorui/src/layout/components/Header/HeaderTab.vue`
- 顶部用户区：`wimoorui/src/layout/components/Header/HeaderAvatar.vue`
- 通用表格：`wimoorui/src/components/Table/GlobalTable/index.vue`
- 全局视觉令牌：`wimoorui/src/assets/css/global.css`
- 产品资料页：`wimoorui/src/views/erp/baseinfo/material/index.vue`
- 海外仓计划页：`wimoorui/src/views/erp/warehouse/overseas/plan/index.vue`
- 发货步骤页：`wimoorui/src/views/erp/shipv2/shipment_add/shipstep/components/header.vue`
- 首页看板：`wimoorui/src/views/dashboard/index.vue`
- 财务账户页：`wimoorui/src/views/erp/finance/account/index.vue`

可以直接支撑结论的结构特征：

- 左侧导航固定宽度 `64px`
- 顶部操作栏固定高度 `34px`
- 主内容区最小宽度 `1280px`
- `GlobalTable` 在 `views` 中被使用约 `185` 个文件
- `el-dialog` 在 `views/layout/components` 中出现约 `334` 个文件
- 视口高度减法布局 `height="calc(100vh - ...)"` 出现在约 `150` 个文件
- 本地 `Header` 头部组件模式在业务页中至少出现 `21` 处

结论：

这不是“品牌视觉驱动”的产品前端，而是“操作效率驱动”的桌面型 ERP 前端。真正可迁移的核心不在单个页面，而在以下三层：

1. 应用壳与导航体系
2. 高复用页面原型
3. 面向跨境业务的数据展示和操作组织方式

## 3. 总体设计思想

### 3.1 桌面优先，不追求移动端适配

该 UI 明确面向大屏办公场景设计，核心目标是让运营、采购、仓储、财务在长时间、高密度操作下保持效率和上下文稳定，而不是追求移动端覆盖。

迁移规则：

- 你的系统应优先保障 `1280px+` 的工作区体验
- 主工作页面不应被设计成消费级响应式网页
- 复杂表格、步骤流、侧栏过滤应默认按桌面使用习惯组织

### 3.2 数据优先，视觉为辅助

页面的大部分空间交给表格、指标、状态、筛选和批量操作，视觉表达是克制的，主要用来服务可读性、分层和状态识别。

迁移规则：

- 主区域优先放“可操作数据”
- 卡片、图表、弹窗都应服务业务判断，不应只是装饰
- 装饰性视觉不要压过数据密度

### 3.3 上下文连续性优先于页面纯净

顶部页签、缓存页面、弹窗操作、展开行、二级详情页的共同目标，是减少用户在多任务切换中的上下文损耗。

迁移规则：

- ERP 页面应该允许用户并行打开多个业务对象
- 详情、编辑、比价、库存、记录，不要都强制跳转全新页面
- 保留“从列表进入详情，再返回原位”的能力

### 3.4 业务原型复用优先于页面个性

Wimoor 的大量页面并不是各做各的，而是在复用少数几种稳定原型：

- 查询头 + 工具栏 + 表格
- 指标卡 + 图表 + 辅助榜单
- 左右主从布局
- 可展开计划表
- 多步骤流程页
- 列表页 + 弹窗二级操作

迁移规则：

- 先定义页面原型，再填充业务模块
- 不要每个模块单独发明布局
- 同类业务应保持相同的筛选位置、操作位置和信息层级

## 4. 应用壳设计规则

## 4.1 壳层结构

应用壳由四个稳定区域组成：

1. 左侧一级导航图标栏
2. 顶部固定页签栏
3. 顶部右侧全局操作区
4. 中央主内容区

对应实现：

- `layout/index.vue`
- `AsideMenu.vue`
- `HeaderTab.vue`
- `HeaderAvatar.vue`

迁移建议：

- 保留“左窄右宽”的桌面 ERP 壳层
- 一级导航负责业务域切换，不负责展示过多文本
- 二级导航可以抽屉、悬浮面板或展开面板承载
- 顶部始终保留工作页签，避免单页来回后退

## 4.2 左侧导航规则

当前导航不是传统“长文本树菜单”，而是“图标一级域 + 抽屉二级组”的结构。

优点：

- 一级导航稳定，占用空间小
- 对采购、仓储、发货、财务等大域切换很快
- 二级菜单可以按业务分组，减少一级导航长度

迁移规则：

- 一级导航只放领域，不放具体页面
- 二级导航按业务分组展示，不要平铺所有链接
- 一级导航图标必须具备高度可辨识性
- 多平台入口可以作为全局浮层或平台切换器，不应分散到每个页面

## 4.3 顶部页签规则

页签是 ERP 的“工作记忆层”。

现有特点：

- 主页固定不可关闭
- 其它页面以 `title` 作为标签
- 支持刷新、关闭左右、关闭其他
- 路由与页签强绑定

保留原则：

- 多任务并行操作必须保留
- 页签应支持快速关闭和恢复上下文
- 同一业务对象可带对象名进入页签标题，例如“编辑产品 SKU123”

升级建议：

- 不要继续使用 `title` 作为缓存主键，容易冲突
- 建议用 `route.name + businessId + mode` 生成稳定 cache key
- 页签状态建议与路由状态分离，避免 query 参数过重

## 4.4 顶部全局操作规则

顶部右侧承载的是“横跨系统的能力”，包括：

- 租户/店铺切换
- 地址工具
- 消息提醒
- 帮助入口
- 账号切换
- 主题切换
- 个人中心

迁移规则：

- 全局工具必须与业务页面解耦
- 店铺、租户、平台切换属于壳层，不属于业务页
- 帮助、通知、账户切换应始终可达

## 5. 视觉系统规则

## 5.1 色彩角色

当前系统的颜色分工非常清楚：

- 主色：橙色 `#ff7315`
- 链接/辅助主操作：蓝色 `#2864c5`
- 成功：绿色
- 警告：橙黄
- 危险：红色
- 信息：灰色
- 工作区背景：浅灰
- 卡片背景：白色

设计含义：

- 橙色用于“系统主动作”和当前品牌识别
- 蓝色用于链接、可点击文本、辅助操作
- 状态色严格语义化，不混用

迁移规则：

- 如果你自己的系统已有品牌主色，可以替换橙色，但要保留“主动作”和“链接色”的角色区分
- 链接色建议与主色分离，否则表格中大量链接会失去可读性
- 语义色不要被品牌色覆盖

## 5.2 字体与层级

现有体系偏务实：

- 正文基准 `14px`
- 表头和说明 `12px`
- 小标题 `16px`
- 指标数字 `18px-24px`

迁移规则：

- 重度 ERP 页面不建议用过大的字号
- 主要信息用 `14px`
- 辅助说明、次级状态、时间、补充字段用 `12px`
- 指标卡数字单独放大，不影响表格密度

## 5.3 间距与容器

稳定间距节奏：

- 页面外边距常用 `16px`
- 卡片内边距常用 `16px/24px`
- 组件组间距常用 `8px/16px`
- 边框圆角 `4px`
- 轻投影用于卡片和主要容器

迁移规则：

- 不要做大圆角、厚投影、强装饰
- ERP 容器应偏克制、扁平、清晰
- 同一系统里页面卡片的 padding 要统一

## 5.4 背景策略

背景层级清晰：

- 应用主背景为浅灰工作区
- 数据容器为白卡片
- 展开态、明细态可用更浅的灰做区分

迁移规则：

- 让“数据容器”从背景里自然凸显
- 不要全屏纯白，容易丢失分区
- 不要全屏深色+高饱和强调，会损伤长时间使用体验

## 5.5 图标与标签

当前图标用途偏功能性：

- 导航识别
- 操作按钮
- hover 辅助动作
- 报表/流程状态提示

标签用途偏业务性：

- 产品标签
- 状态标签
- 分类提示

迁移规则：

- 图标只服务识别和操作，不做无意义装饰
- 标签颜色必须可映射业务语义
- 表格中的标签数量要受控，避免彩色噪声

## 6. 页面原型

## 6.1 原型 A：查询头 + 工具栏 + 数据表

代表页面：

- `views/erp/baseinfo/material/index.vue`
- `views/erp/purchase/process/index.vue`
- `views/erp/warehouse/overseas/stock/index.vue`

标准结构：

1. 顶部筛选区
2. 第二行操作区
3. 主表格区
4. 行内微交互和二级弹层

适用业务：

- 商品资料
- 采购单
- 库存记录
- 广告报表
- 平台订单

迁移规则：

- 筛选永远在表格上方，不放侧边隐藏抽屉作为唯一入口
- 一级动作放左侧，汇总与帮助放右侧
- 表格承担主信息，不要把核心字段拆到过多卡片
- 批量操作默认跟随选择态

## 6.2 原型 B：指标卡 + 图表 + 榜单看板

代表页面：

- `views/dashboard/index.vue`

标准结构：

1. 顶部全局时间/店铺筛选
2. 第一屏指标卡
3. 第二屏趋势图与对比图
4. 第三屏榜单、公告、服务入口

适用业务：

- 首页驾驶舱
- 店铺经营看板
- 广告看板
- 财务总览

迁移规则：

- 看板只承载“总览”，不要塞入过多细节操作
- 指标卡只放关键数字，不放复杂表单
- 图表需要与筛选强联动
- 榜单与公告属于辅助区，不应抢主视线

## 6.3 原型 C：左右主从布局

代表页面：

- `views/erp/finance/account/index.vue`

标准结构：

- 左侧：对象列表或账户列表
- 右侧：对象详情、图表、流水表格

适用业务：

- 账户管理
- 店铺管理
- 仓库管理
- 客户/供应商主档

迁移规则：

- 左侧用于对象切换，右侧用于对象分析
- 左侧卡片要足够短，支持快速扫视
- 右侧区允许混合图表和表格

## 6.4 原型 D：可展开的计划/决策表

代表页面：

- `views/erp/warehouse/overseas/plan/index.vue`
- `views/erp/ship/ship_plan/index.vue`

标准结构：

1. 强筛选头部
2. 计划总览汇总
3. 主表展示 SKU 级计划
4. 展开行承载发货/采购/库存明细

适用业务：

- 补货计划
- 采购计划
- 发货计划
- 库存决策

迁移规则：

- 主表只显示决策必需字段
- 展开层承载高噪声、高细节信息
- 计划类页面必须提供“已选数量/采购量/发货量”之类实时汇总
- 行展开、行编辑、悬浮提示、报表入口是计划类页面的标配

## 6.5 原型 E：多步骤流程页

代表页面：

- `views/erp/shipv2/shipment_add/shipstep/components/header.vue`
- `views/erp/ship/shipment_handing/shipstep/index.vue`

标准结构：

1. 顶部单据上下文
2. 步骤条
3. 当前步骤说明
4. 中央步骤内容区
5. 上一步/下一步/跳过等流程动作

适用业务：

- 发货处理
- 入库出库
- 财务审批
- 加工单处理

迁移规则：

- 步骤流必须显示当前所处阶段和下一阶段
- 每一步都要保留单据上下文
- 可跳步时要明确业务条件
- 步骤页内部仍应复用表格、弹窗、汇总卡

## 6.6 原型 F：弹窗驱动的二级操作

现状非常明显：大量次级操作都通过 `el-dialog` 完成。

适合放入弹窗的任务：

- 编辑标签
- 导入导出
- 记录查看
- 账户新增
- 配置调整
- 对比信息

不适合放入弹窗的任务：

- 复杂长表单主流程
- 需要长期停留的业务对象编辑
- 依赖大量上下文切换的页面

迁移规则：

- 弹窗用于“就地完成”的次级任务
- 主流程仍应保留独立页面或步骤页
- 弹窗宽度可按任务复杂度分层：`400/600/800/1000/80%`

## 7. 通用交互规则

## 7.1 筛选区规则

筛选区通常分两层：

- 第一层：常用筛选，始终可见
- 第二层：高级筛选，放在 popover 或折叠区

跨境 ERP 的常用筛选维度应优先保留：

- 平台
- 店铺/租户
- 国家/站点
- 仓库
- 负责人
- 标签
- SKU
- 时间
- 单据状态

迁移规则：

- 高频筛选不要藏太深
- 高级筛选不应破坏主页面节奏
- 必须始终提供“重置”

## 7.2 操作区规则

操作区一般分左中右三层：

- 左：新增、导入、导出、批量操作
- 中：次级业务操作
- 右：汇总信息、帮助、排序、显示已选等

迁移规则：

- 一级主动作固定在左侧
- 汇总固定在右侧更符合 ERP 扫视习惯
- 帮助入口应在每个高复杂度页面保持可达

## 7.3 表格规则

`GlobalTable` 体现了整个系统的核心表格思路：

- 包装分页、排序、加载、选择、展开、树形
- 统一空态
- 统一回调协议
- 通过 slot 交给业务页定义列

迁移时应保留一个“系统级表格壳组件”。

必备能力：

- 分页
- 排序
- 批量选择
- 展开行
- 懒加载
- 固定列
- 行点击
- 空态
- 统一 loading

列设计规则：

- 第一列通常用于选择、展开或主标识
- 名称/SKU 列必须承担最多信息
- 次级信息放在同一单元格第二行
- 行内辅助操作采用 hover 显示，降低噪声

## 7.4 微交互规则

高频微交互包括：

- hover 显示复制图标
- hover 显示“编辑”小入口
- 单元格点击打开 popover
- 行点击进入详情
- 标签、库存、价格等信息悬浮展开

迁移规则：

- 微交互要轻，不要造成闪烁
- 高价值动作用 hover 显示，低价值动作不要常驻
- 表格 hover 行为应只增强，不应改变布局

## 7.5 详情打开规则

详情的打开方式是分层的：

- 轻量信息：tooltip / popover
- 次级任务：dialog
- 对象详情：独立页签
- 长流程：步骤页

迁移规则：

- 先判断任务复杂度，再决定容器
- 不要所有详情都跳整页
- 也不要所有详情都塞进弹窗

## 7.6 缓存与返回规则

当前系统通过 keep-alive 和页签维护返回上下文，这一点非常重要。

迁移规则：

- 列表页返回后应尽量保留筛选、滚动位置、分页和选中状态
- 多对象并行处理场景应支持多页签
- 编辑页和详情页要尽量携带对象名称，降低迷失感

## 8. 跨境电商 ERP 的业务特定设计规则

## 8.1 多维实体必须前置

跨境 ERP 与普通后台最大的不同，是“实体维度很多”：

- 平台
- 店铺
- 国家站点
- 海外仓 / 本地仓
- 负责人
- 供应商
- SKU / ASIN / 本地编码
- 币种
- 运输方式

迁移规则：

- 这些维度必须进入筛选体系，而不是散落在表格内部
- 店铺、仓库、国家、平台是第一层筛选
- 单据号、SKU、名称是快速定位层

## 8.2 决策页面必须显示汇总

采购计划、发货计划、库存决策页面都强调“已选数量、采购总量、发货总量、库存天数”等汇总。

迁移规则：

- 决策页必须有实时汇总区
- 汇总应贴近操作按钮区域
- 汇总展示不应依赖打开弹窗后才可见

## 8.3 库存必须区分本地、海外、在途、待出入库

Wimoor 的很多表格单元格都会同时展示：

- 本地可用
- 海外可用
- 在途
- 待入库
- 待出库
- 可售天数
- 滞销库存

迁移规则：

- 库存字段不能只给一个总数
- 决策页必须体现库存结构，而不只是库存余额
- 库存相关字段优先采用“两层信息单元格”

## 8.4 单据和流程必须可追踪

发货、采购、调拨、付款请求、账期结算都体现出一个原则：单据是流程实体，不只是记录。

迁移规则：

- 单据页应显示当前阶段
- 操作按钮要与状态绑定
- 时间轴、步骤条或阶段标签要稳定存在

## 8.5 多账户、多租户、多平台切换必须低摩擦

跨境 ERP 常见问题不是单页复杂，而是上下文切换频繁。

迁移规则：

- 租户、平台、店铺切换要放在壳层
- 页面内部不要重复做全局切换入口
- 切换后应尽量维持用户当前位置

## 9. 迁移到你自己的系统时应保留什么

建议保留：

- 桌面优先的壳层结构
- 左侧一级域导航 + 顶部多页签
- “筛选头 + 工具栏 + 数据表”的主原型
- 系统级表格壳组件
- 决策页的实时汇总区
- 步骤流页面
- 弹窗承载次级任务
- 白卡片 + 灰工作区 + 低饱和视觉
- 双色角色体系：主动作色 + 链接色

## 10. 迁移时建议升级什么

这些是 Wimoor 现有实现里值得保留思路、但不建议原样照搬的点：

### 10.1 不要继续依赖大量 `calc(100vh - x)`

问题：

- 高度耦合页头尺寸
- 页面一改动就需要到处改高度
- 弹窗、展开行、工具栏变化后容易抖动

改进建议：

- 建立统一的 `PageShell`
- 用 flex 布局和容器自适应代替手写高度差
- 只在极少数超长表格中保留固定高度策略

### 10.2 不要用 `query.title` 作为缓存主键

问题：

- 标题变了缓存就失效
- 同名页面容易互相污染

改进建议：

- 用稳定业务 key 生成 cache id
- 页签标题只负责展示，不负责缓存索引

### 10.3 不要把主题切换塞进“回首页”动作

当前 `AsideMenu.goHome()` 同时处理主题切换和回首页，语义混杂。

改进建议：

- 首页跳转、主题切换、平台切换要彻底分开
- 全局动作一项只负责一件事

### 10.4 不要让页面自己拼太多筛选组件

Wimoor 的筛选头很强，但不同页面重复拼装较多。

改进建议：

- 抽象成统一 `FilterBar`
- 统一常用筛选组件：店铺、仓库、负责人、标签、类目、时间
- 用 schema 配置筛选顺序和字段

### 10.5 不要过度依赖弹窗承载复杂编辑

改进建议：

- 短任务用弹窗
- 复杂长流程用步骤页或详情页
- 避免一个弹窗内再套大量二级弹窗

## 11. 推荐的迁移落地顺序

### 第一阶段：先搭壳

- 左侧一级导航
- 顶部页签
- 顶部全局区
- 主工作区

### 第二阶段：抽系统级基础件

- `PageShell`
- `FilterBar`
- `ActionBar`
- `DataTable`
- `SummaryBar`
- `StepPage`
- `EntityDialog`

### 第三阶段：先迁原型，再迁模块

建议先按原型迁移：

1. 查询表格页
2. 计划决策页
3. 多步骤流程页
4. 看板页
5. 左右主从页

不要直接按“采购、发货、财务”模块一个个硬搬。

### 第四阶段：最后再做品牌化

- 替换主色
- 替换图标风格
- 替换字体
- 微调圆角、阴影、边框

先保证原型成立，再做视觉升级。

## 12. 建议的页面规格模板

你在自己系统里定义任何一个 ERP 页面时，建议先回答下面这些问题：

1. 这个页面属于哪一种原型？
2. 用户在这里做的是查询、决策、录入，还是流程推进？
3. 顶部必须暴露哪些高频筛选？
4. 右侧需要展示哪些实时汇总？
5. 主区域是表格、图表还是步骤内容？
6. 哪些信息应放展开行、popover、dialog？
7. 返回列表后需要保留哪些上下文？
8. 当前页面对应哪个跨境维度：平台、店铺、国家、仓库、供应商、币种、运输方式？

## 13. 最终设计规则清单

### 13.1 布局规则

- 左侧用窄导航承载业务域，顶部用页签承载任务上下文
- 主工作区始终服务桌面端
- 页面容器统一使用白卡片 + 灰背景分层

### 13.2 信息规则

- 筛选在上，数据在中，辅助区在右
- 名称/SKU 单元格承担第一识别信息
- 次级信息优先放同单元格第二行

### 13.3 交互规则

- 一级动作在左，汇总在右
- 详情容器按任务复杂度分为 popover、dialog、detail page、step page
- 列表返回必须尽量保留上下文

### 13.4 视觉规则

- 主色用于主动作，蓝色用于链接
- 正文 `14px`，辅助 `12px`
- 边距和卡片 padding 统一到 `8/16/24` 节奏

### 13.5 跨境业务规则

- 平台、店铺、国家、仓库、负责人、供应商、SKU、时间是优先筛选维度
- 计划与库存页面必须显示汇总
- 单据必须体现阶段和状态

## 14. 一句话总结

这套 UI 的本质不是“后台管理模板”，而是一套为跨境电商 ERP 高密度运营场景服务的桌面型工作台。迁移时最应该保留的是它的页面原型、数据优先级和上下文连续性，最应该升级的是缓存键、布局适配方式和基础组件抽象层。
